# nemo Provider

The nemo provider deploys applications made of containers on any Docker host, with [nemo](https://github.com/sntns/nemo): Compose on one machine, Swarm on many, without Kubernetes.

[nemo](https://github.com/sntns/nemo) turns each compose file into a **bundle**: a versioned [CNAB](https://cnab.io) package of its services, their images pinned by digest, and the installer that deploys them. A **stack** says which bundles go on one target, and with which parameters and credentials. The provider's one resource, [`nemo_stack`](resources/stack), is that stack: each apply installs the bundles it lists, in the order of their dependencies, upgrades those installed and uninstalls those it no longer lists. The data source [`nemo_bundle`](data-sources/bundle) finds the latest version of a bundle in a registry, and [`nemo_stack`](data-sources/stack) reads a stack its target has. With Terraform 1.14, the list resource `nemo_stack` finds every stack of a Docker for `terraform query`.

```terraform
terraform {
  required_providers {
    nemo = {
      source = "sntns/nemo"
    }
  }
}

# The Docker of every stack whose target gives neither host nor context.
# Without it, the environment's: DOCKER_HOST, the current docker context, or the local socket.
provider "nemo" {
  host = "tcp://10.1.0.10:2376"
  tls = {
    ca   = { path = "certs/ca.pem" }
    cert = { path = "certs/cert.pem" }
    key  = { env = "DOCKER_KEY" }
  }
}
```

## What you need

- **Bundles**, built from compose files with `nemo bundle build` and kept in an OCI registry, an OCI layout directory or a `bundle.json`. The [getting started guide](guides/getting-started) builds one.
- **A Docker** the provider reaches: the local socket, `ssh://`, `tcp://` with TLS, or a docker context. The machine Terraform runs on needs no Docker of its own when the target is remote.

The provider embeds nemo's library: deploying needs no nemo CLI, only building bundles does. The records of a stack's installations are kept on its target, so `nemo status` and `nemo logs` work from any machine that imported the stack's `manifest` output.

## Compatibility

| | Version |
|---|---|
| Terraform | 1.0 or later; 1.11 or later for write-only credentials (`value_wo`) |
| OpenTofu | 1.6 or later; 1.11 or later for write-only credentials (`value_wo`) |
| Docker Engine on the target | any; in Swarm mode for `swarm`. nemo's installer brings Compose, the target needs no plugin |

The provider is published on the [Terraform Registry](https://registry.terraform.io/providers/sntns/nemo) and the [OpenTofu Registry](https://search.opentofu.org/provider/sntns/nemo), as `sntns/nemo` on both.

## Connection

The provider's `host` or `context`, with its `tls`, is the Docker of every stack whose `target` gives neither `host` nor `context`: several stacks on one swarm give it once. A stack's own `target.host` or `target.context` comes over it. Changing it moves no stack: the next plan reads them on the new Docker.

## Schema

### Optional

- `context` (String) A docker context to reach the Docker of the stacks with, instead of `host`.
- `host` (String) The address of the Docker of the stacks: `tcp://`, `ssh://user@host` or `unix://`. With neither `host` nor `context`, the environment's: `DOCKER_HOST`, the current docker context, or the local socket.
- `tls` (Attributes) The TLS of a `tcp://` host, in PEM, for the stacks that give no `target.tls`. Each part is read from a source, as a credential is. (see [below for nested schema](#nestedatt--tls))
